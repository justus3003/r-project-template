# R Blueprint Project

Template for R projects, structured as an R package, with modern tooling:
**rv** (packages), **air** (formatter), **jarl** (linter), **testthat + covr** (tests), **Quarto** (notebooks),
**prek/pre-commit** and **GitHub Actions**.

## To-Do's

- [ ] Rename the package: `DESCRIPTION` (`Package:`), `tests/testthat.R`, `R/`, `_pkgdown.yml`
- [ ] Set author, e-mail and copyright holder in `DESCRIPTION` and `LICENSE`
- [ ] Set the R version: `rproject.toml` (`r_version`), `DESCRIPTION` (`Depends`), `.github/actions/setup-r-env/action.yaml`
- [ ] Install the tools: `rv`, `air`, `jarl`, `quarto`, `prek` (or `pre-commit`), `make`
- [ ] Run `./setup.sh` (runs `rv sync` and installs the Git hooks)
- [ ] Commit `rv.lock` (generated by `rv sync`)
- [ ] Review the GitHub workflows (see notes below)

## Structure

| Path | Purpose |
|---|---|
| `DESCRIPTION`, `NAMESPACE`, `R/`, `man/` | R package (source code, docs via roxygen2) |
| `tests/` | testthat (3rd edition) |
| `notebooks/` | Quarto notebooks (`_quarto.yml`, `example.qmd`) |
| `data-raw/` | Raw data and preparation scripts (contents are gitignored) |
| `rproject.toml`, `rv.lock` | rv: configuration and lock file (like `pyproject.toml`/`uv.lock`) |
| `air.toml`, `jarl.toml` | Formatter and linter configuration |
| `.pre-commit-config.yaml` | Git hooks (gitleaks, air, jarl, roxygen2, basic checks) |
| `.vscode/` | Optional editor settings for VS Code / Positron (format on save with air) |
| `Makefile` | Tasks (replaces `poe`) |
| `.github/` | CI workflows, composite action, Dependabot |

## Tasks

```bash
make help          # list all tasks
make sync          # install packages (rv sync)
make format        # format code (air)
make lint          # run the linter (jarl)
make document      # roxygen2: update NAMESPACE and man/
make test          # run tests
make cov           # test coverage
make check         # R CMD check
make render        # render Quarto notebooks
make ci            # format-check, lint, test, check
```

## Managing dependencies

- Runtime dependencies: in `DESCRIPTION` under `Imports:` **and** in `rproject.toml` under `dependencies`
- Development tools (devtools, testthat, ...): only in `rproject.toml`
- Then run `rv sync` and commit `rv.lock`

## Notes

- **rv activation:** `rv init` creates `rv/scripts/activate.R` and `rv/scripts/rvr.R` and adjusts `.Rprofile`. The bundled
  `.Rprofile` sources these scripts if they exist. On a fresh checkout `rv sync` is enough. If `rv init` refuses to run because
  `rproject.toml` already exists, see the rv docs: https://a2-ai.github.io/rv-docs/
- **CI:** The composite action `setup-r-env` installs rv via its install script and points `R_LIBS` at the rv library.
  The jarl installation in `.github/workflows/code-style.yaml` uses the installer from the GitHub releases. Check the
  URL/version against https://jarl.etiennebacher.com and pin versions as needed.
- **Dependency review:** The GitHub action does not know CRAN, so `rv.lock` is not evaluated. It remains useful for
  GitHub Actions dependencies.
- **Editor settings:** `.vscode/` is optional and only relevant for VS Code / Positron. Delete it if you use another editor.
  JetBrains IDEs (e.g. DataSpell) store their settings in `.idea/`, which is gitignored and excluded from the package build.
- **Static type checking:** R has no equivalent of `ty`. `R CMD check` and `checkmate` validation fill this role.
